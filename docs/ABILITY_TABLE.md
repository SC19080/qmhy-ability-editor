# 技术笔记：种族值表与特性编号的逆向

以下结论基于对《漆黑的魅影 5.0EX+BW No-Exp》（32MB，ROM code `BPEE`，绿宝石底版）
的纯静态分析 + ROM 内部名表互证，全部可复现。

## 1. 表定位

- 以 19 只种族值 100% 确定的精灵构造 8 字节特征码（6 字节种族值 + 属性对）全 ROM 搜索
- 脱壳忍者（HP=1，全图鉴唯一）仅 1 处命中：`0x3224F0`
- 18 个锚点相对距离全部为 28 的整数倍 → 步长 28、单张连贯大表
- 表基址（槽 0 = 妙蛙种子）：`0x3203E8`，有效条目 411 条

## 2. 条目结构（28 字节，与 pokeemerald `struct BaseStats` 一致）

| 偏移 | 含义 |
|---|---|
| +0x00..0x05 | HP / 攻击 / 防御 / **速度** / 特攻 / 特防（注意速度在 +3） |
| +0x06..0x07 | 属性1 / 属性2（0..17） |
| +0x08 | 捕获率 |
| +0x09 | 基础经验 |
| +0x10 | 性别比（255 无性别 / 254 全雌 / 0 全雄 / 其余 255-32×雌率） |
| +0x11 | 孵化周期 |
| +0x12 | 初始友好度 |
| +0x13 | 成长曲线（0..5） |
| +0x14..0x15 | 蛋群1 / 蛋群2（1 基） |
| **+0x16** | **特性1（引擎编号）** |
| **+0x17** | **特性2（0 或复写 = 单特性）** |
| +0x18..0x1B | 逃跑计 / 体色 / 填充 |

## 3. 本改版的排布与名表

- 改版使用自定义图鉴序：名表内部编号 id1–251 为第一/二代全国序，
  id252–276 为 Gen5 扩展块（比克提尼/莱希拉姆/捷克罗姆/阿尔宙斯等），id277 起为丰缘序
- **种族值表槽位与名表内部编号满足 `内部编号 = 槽位 + 303`**（全程成立）
- 名表 JP/EN 列是原版绿宝石的旧值（民间汉化残留），CN 列为改版当前名
- 单特性约定：绝大多数单特性条目采用 `a2 == a1` 复写（如盖欧卡 `02 02`）

## 5. 修改方法

修改 `(槽位 × 28) + 22 / +23` 两个字节即可，无需任何代码注入：

```
offset = 0x3203E8 + (slot - (-302)) * 28 + 0x16
```

示例（已字节级验证：与原 ROM 全盘 diff 恰好 5 字节差异）：

| 槽位 | 偏移 | 原字节 | 新字节 | 效果 |
|---|---|---|---|---|
| -302 妙蛙种子 | 0x3203FE | 41 22 | 02 46 | 茂盛/叶绿素 → 降雨/日照 |
| -278 皮卡丘 | 0x32069E | 09 1F | 09 0A | 静电/避雷针 → 静电/蓄电 |
| +63 请假王 | 0x322BEA | 36 36 | 03 03 | 懒惰 → 加速 |

## 6. 验证方法

- 静态：Python 脚本全盘 diff + 锚点复检（工具内置自检，`ABILITY_EDITOR_SELFTEST=1`）
- 动态：mGBA / VBA-M 载入 `xxx_MOD.gba` 观察效果；亦可用 PokemonMemHack 在内存中复核
